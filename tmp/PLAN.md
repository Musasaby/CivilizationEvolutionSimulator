## ② 撤去・地形変更の作業化・湖の埋め立て

### ルール
- **完成した建物の撤去**
  - 自分の建物を「撤去」にすると、守りの兵が歩いていき、建てるのと同じ時間をかけて壊す（兵2人なら半分の時間）
  - 撤去が終わると、**建てたときに払った資源の半分**がもどる
  - 撤去中は、建物は動かない（生産・兵づくり・攻撃が止まる）（Q1）
  - 撤去は途中でやめられる（進み具合は失われる）
  - 首都は撤去できない
- **建築予定地の撤去**：すぐ消える。誰も作業していなければ（進み具合 0%）全額、作業が始まっていたら半分もどる
- **地形変更**
  - 爆破・山づくり・湖づくり・**埋め立て（新規）**を置くと「地形の予定地」ができ、守りの兵が歩いていって作業する
  - 資源は置いたときに払う。やめると半分（0%なら全額）もどる
  - 場所の制限はなし。遠いほど、兵が長く歩いて守りが薄くなるのが代わりの制限
  - 作業時間の目安：爆破 8秒・山 15秒・湖 12秒・埋め立て 15秒（兵1人のとき）
  - 埋め立て：水を草原にする。費用の目安 🪨60 🪵30。**近代から**使える（山・湖づくりと同じ）（Q2）
  - 地形の予定地は**敵に狙われる**（Q3）。HPを持ち、壊されたら消える。払った資源はもどらない（建物の予定地が壊されたときと同じ）
- 山・湖は、完成する瞬間にも「すべての首都がつながっているか」を確かめる。ふさいでしまう場合は完成させず、資源の半分を返してログに出す（置いた後でまわりの地形が変わることがあるため）

### 作り方
1. **撤去（完成した建物）**
   - 建物に `b.demo`（撤去中か）と `b.demoProg`（0〜1）を足す
   - `sitesOf(c)` の条件に `b.demo` を足す → 今の `assignWork` がそのまま兵を送る
   - `addWork(b, dt)` に「`b.demo` なら `demoProg += dt / def.time`、1 になったら `finishDemolish(b)`」を足す
   - `finishDemolish(b)`：払った資源の半分を返し、`kill(b)` と同じ後片付けをする。ただし爆発の演出は小さくし、撃破のログは出さない。`kill` を「壊された」と「撤去」で分けられるように、引数を1つ足すか、後片付けだけを関数に切り出す
   - `b.paid` がない建物（最初からある建物など）は、`costOf(c, type)` を建てた時代で計算した値を使う
   - 撤去中は `updateBuilding` の最初で return する（生産・兵づくり・タレットが止まる）
   - 足場（`makeScaffold`）を建物に重ねて、撤去中だと分かるようにする
2. **建築予定地の撤去**：`cancelSite(b)` を「`b.progress === 0` なら全額、それ以外は半分」に変える
3. **地形の予定地**
   - `G.buildings` に `type: 'terra'` の予定地として入れ、`b.terra = 'blast' | 'mountain' | 'water' | 'fill'` を持たせる。これで作業の割り当て・足場・HPバーの仕組みをそのまま使える
   - `BUILD.terra` を `hidden: true, noTerr: true` で作る（一覧や領土の計算から外すため）。作業時間は `TOOLS[b.terra].time` から取る
   - 敵からは、ほかの予定地と同じように狙われる（`nearestBuilding` などから外さない）。HPは `BUILD.terra.hp` で決める（目安 80）。壊されたら `kill(b)` で消え、資源はもどらない
   - **山・水のマスには兵が立てない**：`updateJob` で、地形の予定地のときは「となりの通れるマスまで近づけば作業できる」ようにする（`d <= 1.3`）。道順（`flowTo`）は、目的のマスが通れないマスでも、となりまで案内できるかを確かめる。できなければ、となりの通れるマスを目的地にする
   - 完成したら `G.tiles` を書きかえ、`G.dirtyTerrain = true`、`G.flows.clear()`。山・水にしたマスに兵がいたら、近くの通れるマスへ押し出す
   - `useTool` は「その場で変える」をやめ、予定地を置く処理に変える。今の条件チェック（爆破は森・岩場・山だけ、など）はそのまま使い、埋め立ては「水だけ」にする
4. **画面**
   - 「地形を変える」の列に **🔨撤去** と **🏝埋め立て** を足す
   - 🔨撤去を選んでタップ：完成した建物なら撤去を始める／撤去中ならやめる／建築予定地なら消す
   - 建物をタップしたときの情報パネル（`pickHtml`）にも「🔨撤去（半分もどる）」「撤去をやめる」を足す
   - 撤去を選んでいる間は、指している自分の建物を赤く光らせる（`updateHover`）
   - 設計書の「建築中の建物は、クリック →『建築をやめる』で資源の半分がもどる」を新しいルールに書きかえる
5. **AI**：撤去・地形変更は使わない（今もAIは地形の道具を使っていない）

### テスト
- 完成した農場を撤去 → 兵が歩いていき、8秒（兵1人）でなくなり、🪵が12（25の半分）ふえる
- 撤去中の兵舎は兵を作らない／撤去をやめると元にもどる
- 作業0%の予定地を消すと全額、作業が始まった予定地は半分もどる
- 湖の埋め立て：兵がとなりのマスで作業し、完成すると草原になり、兵がその上を歩ける
- 首都をふさぐ山は、置くときにも完成するときにも止められる
- 作業中の兵は戦わない（今の建築と同じ）ことを確かめる
- 敵が地形の予定地を攻撃して壊すと、予定地が消え、資源はもどらない

## ③ 建物一覧

### ルール・見た目
- 上のバーに **🏘 一覧** ボタンを足す。押すと一覧のパネルが開く（PCは右の大きめのパネル、スマホは画面の下から出るシート）
- 建物を**種類ごとにまとめて**表示する。例：「⚔ 兵舎 ×4（石器2・青銅器2）」
- まとまりを開くと、1つずつの行が出る：時代・HPバー・状態（稼働／停止中／建築中◯%／改修中◯%／撤去中◯%）
- 行を押すと、その建物へカメラが動き、建物を選んだ状態になる（今の `focusCamera` と `G.pick` を使う）
- **まとめての操作**（まとまりごと）
  - 兵を作る建物：⏸ 全部停止／▶ 全部再開
  - 🔨 古いものを全部改修（合計の費用を出す。足りない分は、できるところまで）
  - 🗑 全部撤去（まちがい防止に、もう一度押して確定）
- **一覧のいちばん上に**「⏸ 古い時代の兵づくりを全部止める」を置く。止める対象は「同じ種類の兵を作る建物の中で、一番新しい時代より古いもの」
- 絞りこみのタブ：全部／兵づくり／生産／守り（タレット・壁・シールド）／作業中

### 作り方
- HTML に `#blist-panel` を足し、中身はJSで作る。一覧が開いているときだけ、0.5秒ごとに作り直す（毎フレームは作らない）
- ボタンは今の情報パネルと同じく、`pointerdown` を一か所で受けて `data-act` と `data-id` で振り分ける（中身が作り直されても押せるように）
- 建物に通し番号 `b.id` を足す（行とボタンを建物に結びつけるため）
- 改修・撤去・停止は、1つずつの処理（`startReno`・②の撤去・`b.paused`）をくり返し呼ぶだけにする

### テスト
- 兵舎を3つ建て、時代を進めて1つだけ改修 →「古い時代の兵づくりを全部止める」で古い2つだけが止まる
- 行を押すとカメラが動き、情報パネルにその建物が出る
- 一覧を開いたままでも、ゲームが重くならない（建物100個でフレームの時間をはかる）

## ④ 集合所

### ルール
- **集合所（🚩）**：新しい建物。石器時代から建てられる。費用の目安 🪵60 🪨20・建てる時間 12秒・HP 200
  - **領土を広げる**（Q4）。ほかの建物と同じ広さ
  - いくつでも建てられる。攻撃目標（狙った国の首都、または狙った建物）に**一番近い集合所**を使う。集合所がなければ**首都**が集合場所
  - 攻撃目標がないときも集める（Q5）。そのときは**首都に一番近い集合所**（なければ首都）を使う
- **兵の状態**は3つになる：守り／**集合中**／攻撃中（退避中という状態は作らず、集合中にまとめる）
- 攻撃の割合スライダー＝「集合所に集めておく兵の割合」。割合の分だけ、守りの兵が集合所へ歩いていく（建築係は最後に回す＝今と同じ）
- **集合中の兵**
  - 集合所へ歩いている途中の兵も、着いた兵も「集合中」
  - **戦わない・建築や撤去などの作業もしない**。敵に攻撃されてもやり返さず、集合所へ向かう／並んで待つだけ
  - 集合所のまわり（半径 2.5マス）に並んで待つ
  - 集合所の半径3マスの中にいれば、**毎秒 最大HPの3%ずつ回復**する
- **⚔出撃** ボタン：集合中の兵が**全員**（集合所へ向かっている途中の兵も）まとめて攻撃に出る（Q6）
  - 押してから**3秒間はその場で止まって準備**し、3秒後に動き始める。**攻撃できるようになるのも3秒後**から（準備中も戦わない）
  - 行軍は**一番遅い兵の速さに合わせる**（まとまって着くように）。敵を見つけたら各自で戦う
- **🏳退避** ボタン：攻撃中の兵が全員、集合中にもどり、使っている集合所へ歩いてもどる。集合中なので、もどる途中は戦わない。次の出撃を待つ
- 集合所が壊れたら、次に近い集合所（なければ首都）へ移る
- スライダーを下げたとき：まず集合中の兵を守りにもどし、それでも多ければ攻撃中の兵を、首都に近い順にもどす（今と同じ）
- テレポーターは今のまま（攻撃中の兵がワープする）。集合所とまとめるかは、あとで考える

### 作り方
- `BUILD.rally` を足す。見た目は旗と柵の簡単なもの（`makeBuilding` に1つ足す。時代で色を変えるだけでよい）
- 兵の `u.mode` に `'muster'`（集合中）を足す（退避は `muster` にするだけで、別の状態は作らない）
- `rebalance(c)`：割合の人数を「集合中＋攻撃中」で数え、足りなければ守り → 集合中にする
- `rallyOf(c)`：目標に一番近い（目標がなければ首都に一番近い）、完成している自分の集合所を返す（なければ首都）。0.5秒ごとに計算し直す
- 集合所の並ぶ場所：兵ごとに `u.slot`（角度と距離）を決めて、そこへ歩く。重なりを防ぐため
- `updateUnit`：`muster` は「敵を探さず、並ぶ場所へ歩くだけ」。`findEnemyUnit` や `unitAttack` を呼ばない。`assignWork` の対象からも外す（作業をしない）
- 回復：`muster` で、集合所の半径3マスの中にいれば回復する
- 出撃：集合中の兵全員に `u.mode = 'attack'`、`u.readyAt = G.time + 3`、`u.march`（群れの速さ＝一番遅い兵の速さ）を付ける。`G.time < u.readyAt` の間は、動かず・敵も探さない。`moveDir` で `u.march` があればその速さを使う。敵とぶつかったら `u.march` を消す
- 退避：攻撃中の兵を `muster` にもどす（`u.readyAt`・`u.march` は消す）
- 画面：命令の欄に **⚔出撃（集合 N人）** と **🏳退避** を足す。集合所の上に「🚩N」の小さい札を出す
- **AI**：AIも集合の仕組みを使う。集合場所は自分の首都。`aiWave` は「出す人数を集合させる」に変え、全員がそろうか20秒たったら自動で出撃する（出撃後3秒の準備も同じ）。AIは退避しない
  - 集合中の兵は戦わないので、AIの首都が攻められたときは、集合中の兵をすぐ守りにもどす（そうしないと、AIの兵が首都で立ったままやられる）
- AIの攻撃が少し遅くなるので、最初の攻撃までの時間と攻撃の間隔を、自動テストで確かめて調整する

### テスト
- 集合所なし：割合30%にすると、兵の3割が首都のまわりに集まり、出撃を押すまで動かない
- 集合所を2つ建てる：狙う国を変えると、近いほうの集合所へ移る
- 集合中の兵は、敵に攻撃されてもやり返さず、建築の予定地があっても作業しない
- 出撃：途中の兵も含めて全員が出る。押してから3秒は動かず戦わず、3秒後に動き出す。一番遅い兵に合わせて進む（弓兵と騎兵が同じぐらいに着く）
- 退避：攻撃中の兵が集合中になり、戦わずに集合所へもどり、HPが回復する
- 集合所を建てると領土が広がる
- 集合所を壊すと、兵が首都へ移る
- AIの攻撃が、集合してからまとめて来る

## ⑤ 兵種の相性＋自動バランステスト

### ルール
- 兵を4つの系統に分ける

| 系統 | 兵 | 得意な相手（ダメージ2倍） |
| --- | --- | --- |
| 歩兵系 | 戦士・槍兵・剣士・銃兵・小銃兵・光線兵 | 機動系 |
| 機動系 | 騎兵・戦車 | 射撃系・攻城 |
| 射撃系 | 弓兵・ロボット兵 | 歩兵系 |
| 攻城 | 大砲兵 | 建物（3倍、今と同じ） |

- 系統は時代をまたいで効く（石器の戦士でも戦車に2倍）
- タレットには相性をつけない（今回はシンプルにする）
- 兵を作る建物のボタンと情報パネルに「得意：◯◯系／苦手：◯◯系」を出す

### 作り方
- `UNIT_CLASS = { inf: 'foot', cavalry: 'mobile', tank: 'mobile', archer: 'ranged', robot: 'ranged', cannon: 'siege' }`
- `BEATS = { foot: ['mobile'], mobile: ['ranged', 'siege'], ranged: ['foot'] }`、`COUNTER_MULT = 2`
- `unitAttack(u, t)` でダメージを計算するときに、`t` が兵で相性が良ければ2倍にする。弾（`spawnProjectile`）は計算済みのダメージを運ぶだけなので、そのままでよい
- **AI**：相手の軍の系統の割合を見て、得意な兵を作る建物を優先して建てる（`aiThink` の重みを少し変える）。これがないと、プレイヤーだけが相性を使えて有利になる

### 自動バランステスト
目的は、**時代ごとの強さの差を縮めるかどうか**を数字で決めること。

1. **小さな戦いのテスト**（先にやる。速くて分かりやすい）
   - 何もない平地に、2つの軍を向かい合わせて置き、どちらが勝つかと残りのHPを記録する
   - 比べる組み合わせ：同じ費用の「相性で有利な1時代前の兵」と「相性で不利な今の時代の兵」。2時代差でも比べる
   - 目標：**1時代差なら相性で有利なほうが勝つ。2時代差なら新しいほうが勝つ**
   - この目標に届かなければ、時代ごとの強さの上がり方（今は1時代で約1.5倍）を1.3倍ぐらいに下げて、もう一度はかる
2. **通しのテスト**
   - プレイヤーをAIに動かさせ、「時代を急ぐ」「兵を増やす」「バランス」の3つの作戦で、20分×地形5種類を回す
   - 生き残った時間・到達した時代・倒した敵の数を表にする
   - 目標：どれか1つの作戦だけが、いつも勝つ状態になっていないこと
- テストのスクリプトは `tools/balance/` に置き、Playwright で `?debug` のページを開いて `ces.step()` で進める。`ces` に、軍を置く・作戦を決めるための関数を足す
- 結果は `tools/balance/results.md` に残す

### テスト
- 戦士（歩兵系）が騎兵に2倍、弓兵が戦士に2倍のダメージを与える
- 大砲兵は建物に3倍、騎兵から2倍のダメージを受ける
- AIが、プレイヤーの軍に合わせて作る兵を変える

## ⑥ スマホ縦向きのUI・壁をなぞって置く・兵の状態の表示

### スマホ縦向きのUI
今はPC用のパネルがそのまま出て、画面のほとんどがふさがる（Playwright で 390×844 の画面を確かめた）。
**目標：縦向きのスマホで、地図が画面の6割以上見えること。ボタンは指で押しやすい大きさ（44px以上）にすること。**

- 画面幅 600px 以下の縦向き（`@media (max-width: 600px) and (orientation: portrait)`）だけ、次の並びにする

```
┌──────────────────────────┐
│🍖168 🪵240 🪨96 📘27 👥2/3│ ← 資源（1行・小さい字）
│石器 前3098年 ⏸▶▶▶ 🏘 👑 │ ← 時代・速さ・一覧・命令
├──────────────────────────┤
│                          │
│                          │
│         地図             │
│                          │
│  ログ（最新2行だけ）      │
├──────────────────────────┤
│ 選んだ建物の情報（出る時だけ）│
├──────────────────────────┤
│🌾 🪓 ⛏ 🏠 🔭 ⚔ 🗼 🚩 → │ ← 建物ボタン（横にスクロール・アイコンと費用だけ）
└──────────────────────────┘
```

- 左のパネル → 下の横スクロールの1列（アイコン＋費用だけ。名前は選んだときに情報の欄に出す）
- 時代のボックス → 上のバーの時代名を押すと開く。進められるときは光らせる
- 右のパネル（文明と命令）→ 👑 ボタンで下から出すシート。ただし **⚔出撃・🏳退避・割合スライダー** はシートを開かなくても押せるよう、地図の右下に小さく出す（守りの見せ場で急いで押すため）
- 操作説明（`#help`）は隠す
- 地図にふれたときにブラウザが拡大・スクロールしないよう、`canvas` に `touch-action: none` を付ける
- PC の見た目は変えない

### 壁をなぞって置く
- 壁を選んでいるとき、押したまま動かすと、通ったマスに壁の予定地をまとめて置く
- 速く動かしてもマスが飛ばないよう、前のマスから今のマスまでを直線でうめる
- なぞっている間は、置く予定のマスを半透明で見せ、合計の費用を出す。**指を離したときに**まとめて置く（①と同じ考え方）。資源が足りない分は置かない
- タッチでは、①の地形の塗りと同じく、指1本で少し動かしてから始め、その間はカメラを止める。ほかの建物では、今まで通り1本指のドラッグでカメラが回る

### 兵の状態の表示
- 命令の欄の「攻撃中・守り・建築」に **集合中** を足す
- 縦向きのスマホでは、上のバーに小さく「🛡5 🔨2 🚩4 ⚔3」と出す

- 壁をなぞると、なぞったマスにだけ予定地ができ、指を離すまで資源が減らない
- PC の画面写真が、前と変わっていない

## 気をつけること（リスク）
- **④が一番大きい変更**。兵の動き（`updateUnit`・`rebalance`・`aiWave`）をまとめて変えるので、AIの強さが変わる。④の後に通しのテストをして、最初の攻撃の時間などを調整する
- **集合中の兵は戦わない**（④）：集合所が敵に攻められると、集めた兵がやり返さずにやられる。集合所は守りの兵やタレットで守る、または急いで出撃する、が対策になる。遊んでみて厳しすぎたら見直す
- **集合所で領土が広がる**（④）：集合所を並べて領土をのばす使い方ができる。費用が安すぎれば上げる
- **山・水のマスの作業**（②）：兵は通れないマスには入れないので、「となりで作業する」を正しく作らないと、兵が予定地のまわりで止まる
- **⑤の目標に届かないとき**：時代ごとの強さを下げると、「時代が進む瞬間」の気持ちよさが減るかもしれない。見た目や新しい兵種の解放など、強さ以外の楽しさで補えるかも一緒に確かめる
- **⑥のスマホ表示**：PCの見た目をこわさないよう、CSSは画面幅の条件の中だけに書く
